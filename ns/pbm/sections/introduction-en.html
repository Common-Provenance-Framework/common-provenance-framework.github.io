Introduction back to ToC

The Provenance of Biological Material Ontology (PBM-O) is the OWL 2 representation of the Provenance of Biological Material (PBM) structures. The PBM structures are specializations of the provenance structures defined in W3C PROV-DM and describe biological material, such as samples, their containers, sources, and standard operating procedures, together with the activities performed on them and the devices involved. They are used together with the Common Provenance Model (CPM), whose terms are defined in CPM-O.

Provenance of samples and derived data answers questions such as which aliquots were in a freezer during a temperature excursion, or how long it took from blood draw to centrifugation.

The primary purpose of PBM-O is to provide stable IRIs, labels, and definitions for the PBM terms, so that they can be referenced from provenance documents in PROV-N, PROV-JSON, PROV-XML, or RDF. PBM-O extends the W3C PROV Ontology (PROV-O), which it imports: every PBM class is a subclass of a PROV-O class.

PBM structures

Each structure is identified in PROV-N and PROV-JSON by a value of the prov:type attribute. In PBM-O each type value corresponds to a class (see Using PBM terms).

Using PBM terms

The following PROV-N example shows a sample that is stored in a storage device. Entities are snapshots of described objects: the sample before storage (ex:sample1) and the stored sample (ex:sample1-stored) are separate entities, both of type pbm:sample. The storage activity uses the first and generates the second. All identifiers and values are illustrative.

document
  prefix ex <https://example.org/>
  prefix pbm <https://www.commonprovenancemodel.org/ns/pbm#>

  entity(ex:sample1, [prov:type='pbm:sample'])
  entity(ex:sample1-stored, [prov:type='pbm:sample'])
  entity(ex:box1, [prov:type='prov:Collection', prov:type='pbm:container'])
  activity(ex:storage1, 2026-09-01T10:00:00Z, -, [prov:type='pbm:storage'])
  agent(ex:freezer1, [prov:type='pbm:storageDevice'])
  used(ex:storage1, ex:sample1, -)
  wasGeneratedBy(ex:sample1-stored, ex:storage1, -)
  wasDerivedFrom(ex:sample1-stored, ex:sample1)
  wasAssociatedWith(ex:storage1, ex:freezer1, -)
  hadMember(ex:box1, ex:sample1-stored)
endDocument

Following PROV-O, the prov:type attribute is expressed in RDF with rdf:type. Standard PROV tools therefore produce the following RDF from the example above (excerpt):

ex:sample1 a prov:Entity, pbm:sample .

ex:sample1-stored a prov:Entity, pbm:sample ;
    prov:wasGeneratedBy ex:storage1 ;
    prov:wasDerivedFrom ex:sample1 .

ex:box1 a prov:Entity, prov:Collection, pbm:container ;
    prov:hadMember ex:sample1-stored .

ex:storage1 a prov:Activity, pbm:storage ;
    prov:startedAtTime "2026-09-01T10:00:00Z"^^xsd:dateTime ;
    prov:used ex:sample1 ;
    prov:wasAssociatedWith ex:freezer1 .

ex:freezer1 a prov:Agent, pbm:storageDevice .

A larger example combining PBM-O with CPM-O across organisations is on the Examples page.

Please note:

  • Type values and classes. The PBM structures use lower-case type values (e.g. pbm:sample), while PBM-O names its classes with a capital letter (e.g. pbm:Sample). As in CPM-O, each type value is declared as a class equivalent to the corresponding PBM-O class, so RDF produced from PROV-N or PROV-JSON is classified correctly.
  • Containers. A container carries two type values, prov:Collection and pbm:container.

Scope of this version

In this version, PBM-O serves primarily as a vocabulary: it declares the PBM classes, provides their definitions, and aligns them with PROV-O. The minimum cardinality restrictions document the mandatory start and end times of the PBM activities but, under the open-world semantics of OWL, they do not validate data. Constraints for checking conformance and further features are planned for future versions.
