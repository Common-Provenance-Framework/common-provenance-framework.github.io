Introduction back to ToC

The Provenance of Data Generation Ontology (PDG-O) is the OWL 2 representation of the Provenance of Data Generation (PDG) structures. The PDG structures are specializations of the provenance structures defined in W3C PROV-DM and describe data generation: the generated data, the data generation activities, and the devices, software, and other agents involved. They are used together with the Common Provenance Model (CPM), whose terms are defined in CPM-O.

The primary purpose of PDG-O is to provide stable IRIs, labels, and definitions for the PDG terms, so that they can be referenced from provenance documents in PROV-N, PROV-JSON, PROV-XML, or RDF. PDG-O extends the W3C PROV Ontology (PROV-O), which it imports: every PDG class is a subclass of a PROV-O class.

PDG structures

Each structure is identified in PROV-N and PROV-JSON by a value of the prov:type attribute. In PDG-O each type value corresponds to a class (see Using PDG terms).

Classprov:type valueSubclass ofDefinition
pdg:Datapdg:dataprov:Entitya provenance structure that represents data.
pdg:DataGenerationpdg:dataGenerationprov:Activitya provenance structure that represents a data generation.
pdg:DataGenerationDevicepdg:dataGenerationDeviceprov:Agenta provenance structure that represents a device for data generation.
pdg:DataGenerationSWpdg:dataGenerationSWprov:Agenta provenance structure that represents a software for data generation.
pdg:DataGenerationOtherpdg:dataGenerationOtherprov:Agenta provenance structure that represents an agent for data generation different from software and device.

Using PDG terms

The following PROV-N example shows a data generation activity that generates data using a device and software. All identifiers and values are illustrative.

document
  prefix ex <https://example.org/>
  prefix pdg <https://www.commonprovenancemodel.org/ns/pdg#>

  activity(ex:sequencing1, 2026-09-12T09:00:00Z, -, [prov:type='pdg:dataGeneration'])
  entity(ex:reads1, [prov:type='pdg:data'])
  agent(ex:sequencer1, [prov:type='pdg:dataGenerationDevice'])
  agent(ex:basecaller1, [prov:type='pdg:dataGenerationSW'])
  wasGeneratedBy(ex:reads1, ex:sequencing1, -)
  wasAssociatedWith(ex:sequencing1, ex:sequencer1, -)
  wasAssociatedWith(ex:sequencing1, ex:basecaller1, -)
endDocument

Following PROV-O, the prov:type attribute is expressed in RDF with rdf:type. Standard PROV tools therefore produce the following RDF from the example above (excerpt):

ex:sequencing1 a prov:Activity, pdg:dataGeneration ;
    prov:startedAtTime "2026-09-12T09:00:00Z"^^xsd:dateTime ;
    prov:wasAssociatedWith ex:sequencer1, ex:basecaller1 .

ex:reads1 a prov:Entity, pdg:data ;
    prov:wasGeneratedBy ex:sequencing1 .

ex:sequencer1 a prov:Agent, pdg:dataGenerationDevice .

ex:basecaller1 a prov:Agent, pdg:dataGenerationSW .

Please note:

  • Type values and classes. The PDG structures use lower-case type values (e.g. pdg:data), while PDG-O names its classes with a capital letter (e.g. pdg:Data). As in CPM-O, each type value is declared as a class equivalent to the corresponding PDG-O class, so RDF produced from PROV-N or PROV-JSON is classified correctly.

Scope of this version

In this version, PDG-O serves primarily as a vocabulary: it declares the PDG classes, provides their definitions, and aligns them with PROV-O. The minimum cardinality restriction documents the mandatory start time of data generation activities but, under the open-world semantics of OWL, it does not validate data. Constraints for checking conformance and further features are planned for future versions.
