# Common Provenance Model website

Static website of the Common Provenance Model (CPM), served at
<https://www.commonprovenancemodel.org>.

## Contents

- Site pages: `/`, `/about/`, `/specification/`, `/usage/`, `/ontologies/`
- Ontologies under `/ns/`, each with HTML documentation (`index.html`, generated by
  [Widoco](https://github.com/dgarijo/Widoco)) and four serializations:

| Ontology | IRI | Files |
|---|---|---|
| CPM-O | `https://www.commonprovenancemodel.org/ns/cpm#` | `ns/cpm/ontology.{ttl,owl,nt,jsonld}` |
| PBM-O | `https://www.commonprovenancemodel.org/ns/pbm#` | `ns/pbm/ontology.{ttl,owl,nt,jsonld}` |
| PDG-O | `https://www.commonprovenancemodel.org/ns/pdg#` | `ns/pdg/ontology.{ttl,owl,nt,jsonld}` |

## How it is served

- GitHub Pages publishes this repository (branch `main`, root folder) at
  <https://mf-16.github.io/CPF-Website/>.
- Planned: `www.commonprovenancemodel.org` is served by an Apache server that forwards
  requests to GitHub Pages and handles content negotiation for the ontology IRIs
  (HTML for browsers, RDF for RDF clients).
- There is deliberately no `CNAME` file: if GitHub Pages were given the custom domain
  while Apache forwards to it, requests would loop.
- The github.io address shows pages without styling and with broken menu links. This is
  expected: all site links start with `/`, so they only work when the site is served at
  the root of a domain.

## Viewing locally

```bash
python -m http.server 8000
```

Run it from the repository root, then open <http://localhost:8000/>. Opening the files
directly (`file://`) does not work, because the ontology pages load their sections with
JavaScript and site links start with `/`.

## Updating the site

The content is generated by the site author with Widoco. Do not edit files here by
hand: fix them in the build and export a new zip. To apply a new export:

```bash
git rm -r -q -- . ':!README.md' ':!.nojekyll'   # remove the old build
unzip -q path/to/public.zip                       # creates public/
cp -r public/. . && rm -rf public                 # move contents to the root
git add -A
```

Removing the old build first matters: unzipping on top would keep pages that were
deleted from the new build. Check the result locally, then commit and push.
